# Прошивка ESP32-C6 (ESP-IDF)

Зчитує ЕКГ (ADS1293, SPI), пульс/SpO₂ (MAX30102, I2C), температуру (TMP117, I2C)
і шле телеметрію на сервер (`web/server.js`) через `POST /api/data` у форматі,
який вже очікує сервер. Поки що без SD-логування — тільки sensor -> сайт.

## Розпіновка

Вичитано зі схеми (`U1` = Seeed XIAO ESP32-C6, підписаний на схемі як
"ESP32_C6 speed studio"). Якщо розводка на реальній платі відрізняється від
схеми — поправити `main/pins.h`.

| Сигнал | Пін плати | GPIO |
|---|---|---|
| SPI SCK (ADS1293) | D8 | GPIO19 |
| SPI MOSI (ADS1293) | D10 | GPIO18 |
| SPI MISO (ADS1293, SDO) | D9 | GPIO20 |
| ADS1293 CS (CSB) | D7 | GPIO17 |
| ADS1293 DRDY (data ready) | D6 | GPIO16 |
| I2C SDA (TMP117 + MAX30102) | D4 | GPIO22 |
| I2C SCL (TMP117 + MAX30102) | D5 | GPIO23 |

MISO/CS тут — це реальна розводка плати (`main/pins.h`), а не те, що
підказує креслення схеми: на фізичній платі CSB і SDO виявились переплутані
між D7/D9 відносно схеми, `pins.h` вже це враховує.

(SD-картка на схемі висить на тій самій SPI-шині, CS = D3/GPIO21, але в цій
збірці не використовується — лишили на потім.)

⚠️ На схемі `VIN` у TMP117 і MAX30102 підключені до **VBUS** (5В з USB), а не
до 3V3. На батарейці без USB ці два сенсори лишаться без живлення — варто
перевірити на реальній платі/схемі, бо для автономного носимого пристрою це,
схоже, не те, що малось на увазі.

## Збірка

Потрібен встановлений [ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c6/get-started/)
(тестувалось на v5.x, ESP32-C6 підтримується з v5.1+).

```bash
cd firmware
idf.py set-target esp32c6
idf.py menuconfig   # -> Medical IoT Device: Wi-Fi SSID/пароль, Server URL, Device ID
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

Налаштування у `menuconfig -> Medical IoT Device`:
- **Wi-Fi SSID / password** — мережа, до якої підключається плата.
- **Server URL** — повний шлях до `/api/data` сервера (`web/server.js`), напр.
  `http://192.168.1.50:3000/api/data`.
- **API-Key** — заповнити, тільки якщо сервер запущено з `API_KEY=...`.
- **Device ID** — `device_id`, який бачитиме панель.
- **Also publish telemetry over MQTT** (вимкнено за замовчуванням) — якщо
  увімкнути, той самий JSON додатково шлеться в MQTT-брокер (`MQTT broker
  URI`, опційно `username`/`password`) на топік
  `wearable/<Device ID>/data` — саме це приймає `web/src/mqtt-ingest.js`.
  HTTP POST при цьому нікуди не дівається, працює паралельно.

## Що робить прошивка

- `wifi_connect.c` — підключення до Wi-Fi (STA), з ретраями.
- `ads1293.c` — мінімальна конфігурація ADS1293 на 1 відведення (канал 1),
  читання по перериванню DRDY. Регістри й початкова конфігурація взяті з
  відкритої бібліотеки ProtoCentral (`protocentral-ads1293-arduino`) —
  **варто звірити з даташитом TI SNAS602C**, якщо показання виглядають дивно.
- `telemetry_mqtt.c` — опційна (вимкнена за замовчуванням) паралельна
  публікація того самого JSON в MQTT-брокер, топік
  `wearable/<Device ID>/data`.
- `tmp117.c` — читання температури (°C).
- `max30102.c` — драйвер FIFO + **спрощена, нека́лібрована** оцінка
  пульсу (порогові переходи) і SpO₂ (ratio-of-ratios за емпіричною формулою).
  Це не проприєтарний алгоритм Maxim — для курсового проєкту достатньо, але
  не видавати за клінічно точне вимірювання (про це й так написано в
  дисклеймері в корені README проєкту).
- `main.c` — зводить усе разом: таска читання ЕКГ (чекає DRDY), таска опитування
  MAX30102 (~100 Гц), і раз на секунду збирає накопичені відліки ЕКГ + останні
  hr/spo2/temp в один JSON і шле `POST /api/data`.

Поле `battery` поки не шлеться: на цій схемі немає виводу напруги батареї на
АЦП-здатний пін (±BAT ідуть напряму в термінали зарядного роз'єму плати) —
щоб його мати, треба підключити дільник напруги з батареї на вільний ADC-пін
і дописати зчитування в `main.c`.

## Чесно про обмеження

Це не компілювалось і не прошивалось на реальному залізі в цьому середовищі
(тут немає встановленого ESP-IDF toolchain) — перша збірка майже напевно
покаже дрібні помилки компіляції чи малопрацюючу конфігурацію ADS1293, яку
треба буде підрихтувати по даташиту під час реального налагодження на платі.
